# Практическая работа: нормализация БД до 3НФ

## Тема

**Нормализация реляционной базы данных до третьей нормальной формы (3НФ).**

Пример предметной области — онлайн-каталог фильмов по типу Кинопоиска.

## Цель

Научиться:
- определять функциональные зависимости;
- приводить таблицы к 1НФ, 2НФ и 3НФ;
- находить частичные и транзитивные функциональные зависимости;
- отличать транзитивную зависимость от рекурсивной связи;
- строить итоговую ER-диаграмму.

# 3. Приведение к 1НФ

Найдите поля, в которых может находиться несколько значений.

### Требуется

# 4. Приведение к 2НФ

После получения 1НФ найдите таблицы с составными первичными ключами.

Проверьте:

# 5. Приведение к 3НФ

После получения 2НФ проверьте оставшиеся таблицы.

Найдите **транзитивные функциональные зависимости**.

Пример:

~~~
A → B
B → C
следовательно
A → C
~~~

Для каждой найденной транзитивной зависимости:
1. укажите цепочку зависимости;
2. объясните, почему это нарушение 3НФ;
3. определите, какую таблицу необходимо выделить;
4. укажите первичный и внешний ключи новых таблиц.

# 6. Транзитивная и рекурсивная зависимости — это не одно и то же

Обязательно письменно объясните разницу.

### Транзитивная зависимость

Это цепочка функциональных зависимостей между атрибутами:

~~~
A → B
B → C
~~~

В результате:

~~~
A → C
~~~

Именно такие зависимости устраняются при приведении таблицы к 3НФ.

### Рекурсивная связь

Рекурсивная связь возникает, когда запись таблицы ссылается на другую запись **той же таблицы**.

Например, в таблице Genre:

| GenreID | GenreName | ParentGenreID |
|---:|---|---:|
| 1 | Кино | NULL |
| 2 | Фантастика | 1 |
| 3 | Научная фантастика | 2 |

Здесь ParentGenreID является внешним ключом на GenreID той же таблицы.

Это **не то же самое**, что транзитивная функциональная зависимость.

Рекурсивная связь сама по себе **не является нарушением нормализации**.

Она может и должна существовать в корректной нормализованной БД, если предметная область содержит иерархию:

~~~
Жанр
└── Фантастика
    └── Научная фантастика
        └── Космическая фантастика
~~~

### Требуется

Добавьте в итоговую ER-модель иерархию жанров через рекурсивный внешний ключ:

~~~
Genre.ParentGenreID → Genre.GenreID
~~~

Объясните, почему наличие этого внешнего ключа не означает нарушение 3НФ.

# 7. Итоговая ER-диаграмма

После всех преобразований постройте итоговую ER-диаграмму.

На ней должны быть показаны:
- сущности;
- первичные ключи;
- внешние ключи;
- связи между сущностями;
- связь жанра с родительским жанром.
